1. Project Overview
EXION OrderFlow is a business web application for managing customers, products, quotations, discounts, approvals, order status and delivery documentation. The system is intended to replace a manual sales quotation workflow with a controlled, role-based digital process.
The project is being built from zero. The supplied screenshots are reference designs for the Salesperson experience and related quotation/delivery documents. The first objective is to show the client a polished demo with real server-side data persistence rather than a frontend-only mockup.
1.1 Main business objective
Allow salespeople to manage their customers and create quotations quickly.
Allow salespeople to browse a controlled product catalog with fixed product information and prices.
Store quotations and business data centrally in Supabase.
Route quotations through an approval workflow.
Restrict users according to their role and permissions.
Generate professional quotation and delivery-note documents.
Provide an admin control layer for products, inventory, users, settings and approvals.

6.2 Discount approval logic
The source requirement explicitly states that a salesperson may give up to 25% discount and that more than 25% requires approval from higher authority.
If discount is 0–25%, the salesperson may continue according to normal quotation rules.
If discount exceeds 25%, the system must require higher-authority approval.
The quotation should enter a pending approval state rather than bypassing the approval process.
The approver can approve or reject the request.
The decision, approver and timestamp should be stored in the database.
Once approved, salesperson editing must be blocked according to the stated rule.
7. Security &amp; Server-Side Rules
Authentication through Supabase Auth.
Role stored in a controlled user profile/role structure.
Supabase Row Level Security (RLS) for database-level access control.
Server-side validation for quotation creation and approval.
Salesperson can only access their own customers/quotes unless the business later authorizes shared access.
Salesperson cannot update product master prices/names/images.
Salesperson cannot modify inventory/settings.
Approved quotations are protected from salesperson edits.
Admin approval actions must be authorized server-side.
All important status changes should be recorded in an audit/history table.
Never expose service-role database credentials in browser code.

12. Data Integrity &amp; Business Rules
Prices should come from the controlled product catalog.
Salesperson cannot modify master product price.
Stock availability should be checked before accepting a requested quantity.
The reference screens show stock labels such as In Stock, Low Stock and Out of Stock, plus expected availability dates.
Discount rules must be enforced consistently in both UI and server-side validation.
VAT should be configurable, with 15% used in the supplied quotation reference.
Quotation totals should be calculated server-side before final persistence/approval.
Approved records should remain immutable to the salesperson.
Important actions should have timestamps and responsible user IDs.
